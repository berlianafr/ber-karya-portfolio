SEAT: From Votes to Elected Legislators, Automated.

Project name: SEAT (Seat Allocation & Electoral Candidate Selection)

Project type:

  • Personal
  • Solo

Tools & skills:

  • Automation
  • Google Apps Script
  • Google Sheets
  • Gemini API

About

SEAT is an automation tool designed to calculate seat allocation for political parties using the Sainte-Laguë method and identify elected candidates directly from election results documented in Formulir D Hasil. The tool integrates AI-powered data extraction, human verification, and automated calculations into a single workflow, reducing repetitive manual work and minimizing the need to switch between different tools while keeping the results verifiable.

The Journey from Concept to Completion

TL;DR: Identified manual bottlenecks in the seat allocation and electoral candidate selection workflow, developed an automated solution, and iteratively refined it through testing and user feedback, including AI-powered vote extraction and usability improvements.

What’s the Problem?

The existing workflow has several pain points:

  1. Data transcription: Vote counts must be manually transcribed from scanned Formulir D Hasil PDF documents into spreadsheets.
  2. Seat allocation: The seat allocation is not calculated by regularly ranking the highest-voted party, but requires the Sainte-Laguë method. Due to this allocation mechanism, the Sainte-Laguë method is applied using spreadsheet formulas and manual calculations/reasoning.
  3. Candidate selection: Users must refer back to the Formulir D Hasil PDF documents to identify candidates with the highest vote counts from each allocated party and identify who gets elected.

These steps are repeated across multiple electoral districts, making the process time-consuming and repetitive. Switching between scanned documents, spreadsheets, and manual calculations also increases the risk of transcription errors and inconsistencies.

Here is My Solution

SEAT integrates AI-powered data extraction, human verification, and automated electoral calculations into a single workflow using Google Apps Script, Gemini API, Google Sheets, and Google Drive. Google-based tools are used because they are familiar to users and already integrated into their existing work processes.

  1. Upload: Users upload one or multiple Formulir D Hasil PDF documents. When multiple files are uploaded, SEAT automatically queues them and processes up to two PDFs concurrently.
  2. Extract: The Gemini API extracts vote counts from each PDF document. If extraction fails, users can retry the process or enter the vote counts manually.
  3. Validate & Verify: SEAT performs system-level validation on the extracted data and displays warnings when inconsistencies are detected. Users then review and verify the data or manually input the vote counts when necessary.
  4. Calculate: Once verified, users can save and proceed with the data for each electoral district. Google Apps Script generates a spreadsheet containing four sheets with predefined formulas, while Google Sheets handles the seat allocation calculations using the Sainte-Laguë method and identifies elected candidates based on their vote counts.
  5. Generate District Recap: After processing individual electoral districts, users can optionally combine the results into a district recap. SEAT generates a consolidated spreadsheet, and Google Sheets calculates the combined results.
  6. Store & Access: Generated spreadsheets are automatically saved to a centralized Google Drive folder, making the results accessible for future reference.

In short, AI extracts. Humans verify. The system calculates and generates.

How Was It Built?

The development of SEAT followed an iterative approach. The application was gradually developed and refined through multiple rounds of self-testing, with feedback informing improvements to its functionality, automation, and usability.

1. Workflow Analysis

  • Studied the existing seat allocation and electoral candidate selection workflow.
  • Identified repetitive tasks and potential automation opportunities.
  • Defined system requirements and user use cases.

2. Core Functionality Development

  • Developed Google Apps Script to automate seat allocation using the Sainte-Laguë method.
  • Implemented the logic to identify elected candidates based on party seat allocation and candidate vote counts.

3. Self-Testing 1: Core Functionality

Findings
  • Manually transcribing vote counts from Formulir D Hasil PDFs remained a repetitive task.
  • The application needed to reduce dependence on manual data entry.
Improvements
  • Integrated the Gemini API to automate vote count extraction directly from PDF documents.

4. Self-Testing 2: Automation & Workflow

Findings
  • AI extraction could occasionally fail due to Gemini API errors.
  • Users needed an alternative when automated extraction was unsuccessful.
  • Extracted data required system-level validation before user verification.
  • Processing multiple electoral districts required a more efficient workflow.
Improvements
  • Implemented retry functionality and warning notifications when extraction fails.
  • Added manual vote count entry as a fallback mechanism.
  • Implemented automated data validation before user verification.
  • Enabled multiple PDF uploads with automated queue management, processing up to two PDFs concurrently.

5. Self-Testing 3: Usability & User Experience

Findings
  • Users needed a way to track their processing activities and access previously generated results.
  • Generated spreadsheets needed centralized storage and easier access.
  • Users needed to perform repeated calculations without losing access to the action buttons.
  • The interface required clearer navigation and instructions.
Improvements
  • Implemented individual processing histories (Riwayat Saya).
  • Centralized generated spreadsheets in a Google Drive folder.
  • Added an option to open the centralized Drive folder directly from the history pop-up.
  • Enabled link-based access to generated spreadsheets.
  • Improved the interface to support repeated calculations.
  • Added English/Indonesian language selection.
  • Refined the layout, section organization, and button labels.

6. Final Refinement

  • Addressed remaining usability issues.
  • Refined the extraction, validation, and manual entry workflows.
  • Conducted final checks to ensure the application worked as intended.

7. Final Demonstration

  • Presented the completed SEAT application and demonstrated its end-to-end workflow, from PDF upload to automated seat allocation and elected candidate identification.
The Challenges

SEAT runs on the free tier of the Gemini API, which has lower priority during high-demand periods and sometimes returns errors. To keep the tool usable, I added retry logic, added clear error messages so users can re-run the extraction, and kept manual input as a fallback. In a production setting, a paid tier would remove most of these failures.
